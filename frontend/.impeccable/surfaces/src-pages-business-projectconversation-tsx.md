# PAKAR project conversation

Scope: the user-approved **Chat & ide** project tab, headed **Ruang ide**. Visitor mode: **Operate**. Business Analysts and Strategic Planning teams discuss source material, clarify a proposed idea, explicitly save an immutable idea version, then choose whether to analyze that version. One saved project conversation retains its history across changes of idea, version and referenced analysis; these selectors supply context rather than separate chats.

Direction: inherit the IBM Plex, flat white/neutral surfaces, square controls, blue actions and hairlines of the existing workspace. Desktop places the flexible conversation on the left and idea/version/source controls in a 280–340px right column. At 850px and below, conversation comes first and the idea panel follows; **Kelola ide & sumber** jumps to that panel. At 480px and below, context/upload controls stack and the send button spans the column. The bounded, keyboard-focusable history region scrolls independently, preserves a reader's position when inspecting older turns and follows new activity while pinned to the end. Neutral user-message bands and explicit agent identities distinguish speakers without a new visual world. No durable global tokens change; this documentation pass updates only this surface brief and leaves `DESIGN.md` and `.impeccable/design.json` untouched.

Chat and evidence: **Tanya kepada** names Fasilitator PAKAR, Market Agent, Finance Agent, Legal/Compliance Agent and Risk Agent. One paid chat turn addresses one chosen agent; it does not automatically run swarm or revise a saved idea. Turns retain their selected idea/version context, request text, responder, execution status and clarification questions. Citation disclosures retain quoted text, source label, optional page and analysis-source links. Source-kind labels distinguish user proposals, synthetic findings requiring validation and conditional calculations; document quotations stay explicitly unverified. **Tambahkan data / temuan** and **Unggah dokumen ide** are separate upload actions, and the source list retains purpose plus extraction/OCR/exclusion status. Images and charts require text support; unavailable content is not silently treated as read evidence.

Idea commitment: typed text, an idea document, a user's explanation or an AI revision suggestion can open an editor for inspection. **Simpan versi ide** is the explicit commitment; closing the editor commits nothing. Versions remain user proposals/assumptions, and prior versions and analysis results stay available. **Versi yang dibahas** can select a saved version. **Analisis ide versi N** explicitly starts a separate two-round stakeholder swarm with four specialists using that selected version, with provider-credit disclosure and no replay of earlier chat. Synthetic projects may choose the labeled fixture path. Analysis creation opens `?tab=swarm`; saved analyses link back through **Diskusikan hasil ini di ruang ide** to `?tab=chat&analysis=<id>` and show their frozen idea/version when present.

States and accessibility: unavailable chat configuration leaves document and idea saving available. An unready referenced analysis explains why chat cannot send and offers choosing no analysis context. The analysis action gives a visible reason when an editor is open, another run is active or model/OASIS runtime is unavailable; the active-run explanation links to that run. Pending chat turns expose cancellation, with the warning that an already dispatched call may still incur provider cost. Failures retain visible errors without automatic AI retries. The composer has a scoped polite, atomic completion announcement for the newly submitted turn, naming the responder without repeatedly announcing the entire history; focus returns to the composer after submission.

Public stakeholder briefing — 2026-11-01: **Brief untuk stakeholder** is an explicit disclosure field, distinct from internal documents, decision questions and the full idea. It starts empty and never copies those sources automatically. In **Ruang ide**, each saved idea revision has its own local draft while the page remains open; selecting another version does not copy the previous version's brief. A draft is not saved permanently until analysis creation stores it in the run snapshot. Launch requires at least 20 trimmed characters; the UI blocks an empty or short brief and explains the requirement. Opening the workspace, uploading sources and saving idea versions remain available without a brief. Intake, automatic project analysis and manually reviewed project analysis use the same shared field.

Brief field treatment: retain the incumbent IBM Plex, flat white/neutral surfaces, square controls and blue focus treatment. The shared textarea uses 16px text, 1.5 line height and a 128px minimum height; helper copy uses 14px text and 1.5 line height. The field has 16px block spacing and an 8px label/input/helper gap. Its visible label and helper are programmatically associated with the textarea. The helper explains what is disclosed, the separation from internal material, the minimum length and when the brief is saved. This is an extension of the existing form system, not a new visual world or new global token scale.

Disclosure and result truth: **Informasi yang dibagikan ke stakeholder** exposes the brief frozen with the run. Stakeholder models use that explicit brief, synthetic viewpoints and permitted visible messages; internal specialists can inspect internal sources. Internal data-model fields are never automatically presented as the stakeholder prompt through a UI action. Saved live analyses without the new information policy show a pre-boundary notice and retain their historical results. These are simulated-role context boundaries, not external-user access control or automatic screening of text deliberately entered into the public brief.

Request recovery: ambiguous launch failures freeze the original request body, brief and nonce across intake, automatic project analysis, manually reviewed project analysis and idea-version analysis. Launch inputs remain locked; only retry of the same request is available, without an automatic paid retry or a switch to another launch mode. Known definitive rejection permits an explicit new action. In the idea flow, only a definitive HTTP 409 `revision_conflict` rejection exposes **Muat konteks analisis terbaru**. That action performs a read-only refresh and resets the rejected request identity; the user inspects the version and explicitly starts again with a new nonce. The shared project launch hook releases its frozen identity for recognized definitive rejection codes and refreshes context before the next explicit launch.
